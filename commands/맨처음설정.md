> **[필수 사전 체크 — 응답 생성 전에]**
>
> 1. `Read ~/.claude/CLAUDE.md` 시도.
> 2. **마커(`<!-- kd:designer-mode:start -->`) 발견** — *이미 켜져 있음*. 다른 응답 만들기 전에 §5 마이그레이션 분기를 처음부터 끝까지 따라간다. 절대 만들지 않는 응답: "이미 켜져 있어요 — 다시 끄려면 `/kdesigner:디자인끄기`로..." 같은 *분기 차단* 응답. 막지 말고 §5 패턴 중 하나로 *처리 결과*를 말한다.
> 3. **마커 부재 또는 파일 부재** — §0부터 정상 흐름.
>
> **이 슬래시는 *프로젝트 단위 작업을 하지 않는다*** — `CLAUDE.project.md` 생성, archived 복원, 사이클 SHA, 빈/기존 분기, DESIGN.md 통합 — 모두 `/kdesigner:프로젝트시작`의 책임. 헷갈리면 §5 끝의 다음 행동 1개로 `/프로젝트시작`을 권유한다.

# 맨처음설정

## 언제 쓰나
디자이너가 *이 컴퓨터에서 처음으로* 디자이너 모드를 켤 때. 한 사용자 환경에서 *1번만* 실행하는 의식 — 켜고 나면 모든 프로젝트에서 한국어·비유·다음 행동 1개 제안 등 페르소나가 자동 작동. 이후 매 프로젝트마다 `/kdesigner:프로젝트시작`으로 *그 프로젝트의 사실*만 박으면 된다.

## 동작

### 0. 사전 도구 확인 (가장 먼저)

디자이너 모드 작동에 필요한 도구가 다 있는지 먼저 확인한다. 다 있으면 짧은 한 줄("도구 확인 완료") 후 §1로 진행. 빠진 게 있으면 *어떻게 깔지* 한국어로 친절히 안내하고 흐름을 *멈춘다* — 사용자가 설치/설정 후 `/kdesigner:맨처음설정`을 다시 호출하면 이어서 시작한다.

#### 0.1 검사 항목 (한 번에 다 검사 후 결과 정리)

먼저 `uname -s`로 OS 판별(`Darwin` = macOS, 그 외 = Windows/Linux). 안내 문구가 OS에 따라 갈라진다.

| 항목 | 명령 | 분류 |
|---|---|---|
| 화면 엔진 (`Node.js`) | `node --version` | 필수 (없으면 작업 자체 불가) |
| 작업 시점 저장 도구 (`git`) | `git --version` | 필수 |
| 사용자 표시 정보 | `git config --global user.name` + `git config --global user.email` | 필수 |
| 도구 설치 도우미 (`Homebrew`) | `brew --version` | macOS 한정 권장 (있으면 다른 도구 설치가 한 줄로 끝) |
| 팀 공유 공간 도구 (`gh`) | `gh --version` | 선택 (인계 단계에서 필요) |
| 팀 공유 로그인 | `gh auth status` | 선택 |

검사 결과는 *한꺼번에* 모은다 — 사용자가 한 번에 무엇을 깔지 알 수 있게(깔다 다시 호출, 또 깔다 다시 호출 흐름 방지).

#### 0.2 모든 도구 OK인 경우

응답 본문 맨 위에 진행 단계 가시화 한 줄 노출 — 메시지는 `plugin/commands/references/tool-check-messages.md` §모든 도구 OK인 경우 그대로. → §1으로 그대로 진행.

#### 0.3 필수 도구 누락 → 흐름 정지 + 친화 안내

영어 에러 한 줄도 노출 X. *해당하는 항목만* 묶어 한 응답에 함께 노출.

**OS·brew 분기 결정**:
- `uname -s` = `Darwin` (macOS) + `brew --version` 성공 → brew 경로 메시지 우선
- `uname -s` = `Darwin` + brew 없음 → macOS brew 없음 fallback 메시지
- Windows / Linux → 공식 사이트 fallback 메시지

각 도구별 *그대로 노출할* 한국어 안내 메시지는 `plugin/commands/references/tool-check-messages.md` §필수 도구 누락 참조:
- `Homebrew` (macOS 권장)
- `Node.js` (필수, OS·brew 분기)
- `git` (필수, OS·brew 분기 — Windows는 공식 사이트)
- `git` 사용자 정보 미설정 (`AskUserQuestion`로 이름·이메일 받아 `git config --global` 실행. 거부 시 흐름 중단)

#### 0.4 선택 도구 누락 → 안내만, 흐름 진행

`gh` 미설치 / `gh auth status` 실패 / 로그인 안 된 경우 — `plugin/commands/references/tool-check-messages.md` §선택 도구 누락 참조. 한 줄만 본문 위에 노출 후 *필수 도구가 다 있다는 전제로* §1로 그대로 진행.

#### 0.5 흐름 정지 시 응답 끝 안내

필수 도구 누락으로 흐름을 멈춘 경우, `plugin/commands/references/tool-check-messages.md` §흐름 정지 시 응답 끝 안내를 응답 마지막에 그대로 노출. 다음 행동 1개 제안(글로벌 §7) 자리는 이 안내가 대체.

### 1. 전역 마커 점검

`Read ~/.claude/CLAUDE.md` 또는 `test -f ~/.claude/CLAUDE.md`로 빠르게 확인하고 분기 결정에만 쓴다:

| 상태 | 분기 |
|---|---|
| 마커(`<!-- kd:designer-mode:start -->`) 발견 | §5 마이그레이션 분기로 |
| 파일은 있지만 마커 없음 | §2 정상 흐름 (백업 후 마커 격리 append) |
| 파일 부재 | §2 정상 흐름 (백업 마커만 만들고 새로 생성) |

### 2. 전역(user-level) 활성화 — 1회 동의

전역 `~/.claude/CLAUDE.md`에 디자이너 페르소나를 박는다. 강제 X — 1회 동의받되 *왜 권장인지*를 옵션 카피에 명시.

`AskUserQuestion`:

> 디자이너 모드를 **이 컴퓨터 전체**에서 켜둘까요?
>
> **켜두면 뭐가 좋나요**: 어느 폴더로 가도 Claude Code가 *처음부터* 한국어로 답하고, 흔한 AI 화면(보라 그라디언트·Inter 폰트·이니셜 아바타 같은 클리셰)을 자동으로 회피하고, 디자이너 친화 톤으로 동작해요. *이 컴퓨터의 Claude Code가 디자이너용 도구로 변하는* 거예요.
>
> **무엇이 바뀌나요**: `~/.claude/CLAUDE.md` 끝에 디자이너 페르소나가 추가돼요(원본은 그대로 백업).
> **언제 되돌리나요**: `/kdesigner:디자인끄기` 한 번이면 원본 그대로 복원돼요.
>
> - **이 컴퓨터 전체에서 켜기 (권장)** — 모든 프로젝트에서 자동 디자이너 모드
> - **이번엔 안 켜두기** — 프로젝트 단위(`/kdesigner:프로젝트시작`)만 작동. 나중에 다시 `/맨처음설정`으로 켜도 OK
> - **잘 모르겠어요** → 기본값: 이 컴퓨터 전체에서 켜기

### 3. 전역 추가 + 백업 (켜기 선택 시)

§2에서 *이 컴퓨터 전체에서 켜기* 또는 *잘 모르겠어요* 선택 시:

1. **백업** — `~/.claude/CLAUDE.md`가 있으면 `~/.claude/CLAUDE.md.kd-backup-<YYYYMMDD-HHmm>`로 `cp` (`date +%Y%m%d-%H%M`). 없으면 빈 백업 마커(`~/.claude/.kd-no-prior-claude-md`) 생성.
2. **추가** — `plugin/templates/CLAUDE.user.md` 내용을 `~/.claude/CLAUDE.md` 끝에 *append*. 시작·끝 마커로 격리:
   ```
   <!-- kd:designer-mode:start -->
   ... (templates/CLAUDE.user.md 내용)
   <!-- kd:designer-mode:end -->
   ```
   `/kdesigner:디자인끄기`가 이 마커 사이만 잘라 복원할 수 있게.
3. 백업 경로를 응답에 1줄로 노출 — "원본은 `~/.claude/CLAUDE.md.kd-backup-YYYYMMDD-HHmm`에 보관해뒀어요".

*이번엔 안 켜두기* 선택 시: 전역 파일은 *건드리지 않음*. §4 검증 스킵하고 §5 다음 흐름 안내로(`/프로젝트시작` 권유). 첫 `프로젝트시작` 시점에 *프로젝트 단위 페르소나 요약*이 `CLAUDE.project.md` 끝에 박혀 단독 동작을 지탱.

### 4. 검증 — 마커·백업 확인

§3 적용했으면:
- `~/.claude/CLAUDE.md`에 시작·끝 마커 쌍이 *정확히 1개*인지 `Read`로 확인. 2쌍 이상이면 중복 추가된 것 → 가장 마지막 쌍만 남기고 나머지는 응답에 경고.
- `~/.claude/CLAUDE.md.kd-backup-*` 백업 파일이 생성됐다면 그 경로 기억(응답에 1줄 노출).

### 5. 이미 켜져 있을 때 — 마이그레이션 분기 (idempotent, 자급식)

**[필수 행동 — 분기 진입 시 절대 생략 금지]**

전역에 `<!-- kd:designer-mode:start -->` 마커가 이미 있다면 흐름을 *막지 않는다*. 아래 §5.0 → §5.1 → §5.2 → §5.4를 *순서대로 반드시 실행*한다. "이미 켜져 있어요"라는 일반 응답을 만드는 것 금지 — 응답은 §5.4 패턴 중 하나여야 한다.

#### 5.0 전역 슬롯 manifest (자급식 — 외부 파일 의존 X)

이 §5의 모든 처리는 *아래 manifest 표만 참조*하면 된다. `templates/` 외부 Read 시도 X — 디자이너 환경에서 그 경로는 resolve 실패한다.

**전역(`~/.claude/CLAUDE.md`) 슬롯 manifest** — `<!-- kd:designer-mode:start -->`/`end` 사이만 대상:

| ID | 한국어 헤더 | 카테고리 | 빈 골격 본문(영역) |
|---|---|---|---|
| `designer-profile` | `## 미학 학습 (자동 누적·디자이너 작성 불필요)` | 컨테이너 | 헤더 + 안내 인용구만 (자식 슬롯 2개가 별도 배치) |
| `avoidance` | `### 피하고 싶은 디자인 (자동 누적 슬롯)` | 자동 누적(빈 골격) | placeholder — `aesthetic-guard`·`feedback-curator`가 사후 누적 |
| `tone-extracted` | `### 평소 톤 (자동 추출 슬롯)` | 자동 추출(빈 골격) | placeholder 3줄 — `aesthetic-guard`가 작업 결과에서 자연스레 누적 |

> 라운드 2(2026-05-12)부터 *디자이너 프로필 인터뷰는 완전 제거*. 라운드 2 후속(2026-05-12)에 한 발 더 — *입력 요구 슬롯 자체를 제거*했다. `fav-references`(레퍼런스 URL)·`portfolio`(포트폴리오 URL)는 빈 골격조차 만들지 않는다 — 디자이너 입장에서 셋업 의식이 "URL 적어주세요" 묻지 않아야 부담 0. `aesthetic-guard`는 본문 *고정 클리셰 회피*(보라 그라디언트·이니셜 박스 아바타·균등 카드 그리드·Inter)를 기본값으로 동작하고, 자동 누적 슬롯 2개(`avoidance`·`tone-extracted`)만 작업 진행하며 채워간다.

#### 5.1 슬롯 상태 분류 — 사용자 파일에서 각 슬롯의 *현재 상태*를 판정한다

1. **반드시** `Read ~/.claude/CLAUDE.md` (사용자 파일).
2. *마커 격리 블록* 안만 대상으로 §5.0 manifest의 각 슬롯에 다음 4-way 분류 적용 (마커 밖 사용자 원본은 손대지 X):

| 상태 | 판정 조건 | 처리 |
|---|---|---|
| **정상** | 마커 ID `<!-- kd:slot:ID -->` + 한국어 헤더 둘 다 있음 | 건드리지 X |
| **마커만 부재** | 마커 ID 없는데 한국어 헤더가 있음 | §5.2-A 마커만 삽입 |
| **둘 다 부재** | 마커 ID 없고 한국어 헤더도 없음 | §5.2-B 빈 골격 추가 |
| **손상 의심** | 같은 마커 ID 2회+ / 같은 헤더 2회+ (마커 0개) | §5.5 즉시 중단 + 보고 |

분류 결과:
- 처리 대상 0개 (모두 정상) → §5.4 "이미 최신" 응답
- 처리 대상 1개 이상 → §5.2로 진행

#### 5.2-A 마커만 삽입 (이전 버전 슬롯 정상화)

"마커만 부재" 분류된 슬롯들에 대해:

1. **백업 우선** — `cp ~/.claude/CLAUDE.md ~/.claude/CLAUDE.md.kd-migrate-<YYYYMMDD-HHmm>`.
2. **마커 한 줄 삽입** — 사용자 파일에서 해당 한국어 헤더의 *정확 일치* 라인을 찾아, 그 라인 *바로 위*에 `<!-- kd:slot:ID -->\n` 한 줄 삽입.
3. **본문은 절대 손대지 X** — 사용자가 채운 모든 내용 보존.
4. *답을 묻지 않음* — 묵묵히 모든 "마커만 부재" 슬롯 처리 후 §5.2-B로.

#### 5.2-B 빈 골격 추가 ("둘 다 부재" 슬롯)

"둘 다 부재" 분류된 슬롯들을 §5.0 manifest의 카테고리에 따라 처리:

**모든 카테고리: 묻지 않음**. §5.0 manifest의 *해당 슬롯 빈 골격*을 마커 + 헤더 + placeholder 본문 형태로 append:
```

<!-- kd:slot:ID -->
## 한국어 헤더 (or ### 으로 manifest 명시 그대로)
> 안내 인용구 (manifest의 빈 골격 본문 그대로)

- {{placeholder 1}}
- {{placeholder 2}}
```

삽입 위치 결정:
1. manifest 순서상 *그 슬롯 직전 슬롯*이 사용자 파일에 있으면 → 그 슬롯 끝 직후에 삽입.
2. 직전 슬롯이 없으면 → *직후 슬롯* 직전에 삽입.
3. 둘 다 없으면 → 사용자 파일 끝(마커 직전)에 append.

placeholder(`{{...}}`)는 그대로 — `aesthetic-guard`가 첫 작업 시 자연스레 1개씩 묻고 채움.

#### 5.3 (없음 — 인터뷰 단계 제거됨)

라운드 2부터 *인터뷰 단계 제거*. 빈 슬롯은 모두 *사후 누적*만 — `aesthetic-guard`가 첫 작업 시 자연스레 1개씩 묻기.

#### 5.4 결과 응답 패턴 (필수 — 일반 "이미 켜져 있음" 응답 금지)

§5.1 분류 결과에 따라 *반드시* 아래 패턴 중 하나로 응답. 절대 만들지 않는 응답: "이미 켜져 있어요 — 다시 끄려면..." 같은 *분기를 막는* 응답.

**Case 1 — 처리 대상 0개 (모두 정상)**:

> 디자이너 모드 *이미 최신 상태*예요. 추가하거나 정리할 게 없어요.
>
> 프로젝트 단위 셋업은 `/프로젝트시작`으로 분리됐어요 — 작업 폴더에서 부르시면 됩니다.

**Case 2 — §5.2-A만 발생 (마커만 삽입, 새 슬롯 추가 0개)**:

> 디자이너 모드의 *내부 표시*를 최신으로 정리했어요. 화면에는 변화가 없고, 다음 업데이트가 더 깔끔하게 동작하도록 표시만 추가한 거예요. 이미 채워두신 내용은 그대로 보존했어요.
>
