# 프로젝트시작

## 언제 쓰나

이 작업 폴더에서 *디자인 작업을 시작*할 때. 빈 디렉토리든 기존 코드 폴더든 한 번에 — *이 프로젝트의 사실*(서비스명·디자인 토큰·컴포넌트 인덱스·스택·DESIGN.md 통합)을 박아 새 대화창에서도 컨텍스트가 이어진다.

## 동작

### 1. 디렉토리 진단 (읽기만)

`Read`/`Bash test`/`Glob`로 빠르게 확인 (중간 응답 노출 X):

| 항목 | 확인 | 분기 영향 |
|---|---|---|
| `./CLAUDE.project.md` 존재 | `Read` | 있으면 §6 마이그레이션 |
| `./CLAUDE.project.md.kd-archived-*` + 본 파일 부재 | `Glob` | §3.1 archived 복원 |
| `./DESIGN.md` 존재 | `Glob` | §2 DESIGN.md 통합 |
| `~/.claude/CLAUDE.md` 마커 | `Read` | 전역 켜짐 여부 (응답 톤) |
| `package.json` 또는 `components/` | `Glob` | §5에서 `import-existing` 권유 |
| 완전 빈 디렉토리 | `Glob` | §5에서 의도 확인 |

**전역 마커 부재** — `/kdesigner:맨처음설정`을 아직 안 켰음. 흐름 막지 않음 — `CLAUDE.project.md` 끝의 페르소나 요약이 단독 동작 지탱. 응답 끝에 *전역 켜두면 더 편해요* 한 줄 권유.

### 2. DESIGN.md 통합 분기

`https://getdesign.md/` 표준의 `DESIGN.md`가 루트에 있으면 *1순위 디자인 시스템 소스*.

| 상태 | 처리 |
|---|---|
| `./DESIGN.md` 존재 | §3.2 `./CLAUDE.md` import 블록에 `@DESIGN.md` 추가 + `CLAUDE.project.md` §디자인 시스템 §철학에 `> DESIGN.md를 1순위 소스로 사용 — 토큰·컴포넌트 규약은 그 파일이 단일 진실.` 한 줄 |
| `./DESIGN.md` 부재 | 묻지 않음. 빈/기존 분기에서 `new-service`·`import-existing`이 *그 안에서* 적절히 |

DESIGN.md *갱신*은 플러그인 책임 X — 사용자가 직접. 외부 표준이라 우리가 관리할 영역 아님.

### 3. 프로젝트 단위 활성화

`./CLAUDE.md` import 라인 처리(2-a 신규 / 2-b 기존 파일에 마커 격리), `CLAUDE.project.md` 생성, archived 복원 분기는 [references/프로젝트시작-import-라인.md](./references/프로젝트시작-import-라인.md).

핵심 원칙:
- *마커 격리*: `<!-- kd:designer-mode:start -->`~`end`로 추가 영역만 감싸 `/kdesigner:디자인끄기`가 정확히 그 부분만 제거.
- *백업 우선*: 기존 `./CLAUDE.md`가 있으면 `.kd-backup-<YYYYMMDD-HHmm>` 백업 후 append.
- *마커 내용은 `@import` 줄만*: 디자인 시스템·페르소나 본문은 박지 않음.

### 4. 사이클 시작 시점 기록

`export-handoff`가 *이번 사이클 변경 파일만* 잡을 기준점. `.claude/.kd-session-base` 박기, 이미 있으면 덮지 X. `.gitignore`에 `.claude/.kd-session-base` 한 줄 append.

자세한 절차는 [references/프로젝트시작-import-라인.md](./references/프로젝트시작-import-라인.md) §4.

### 5. 검증

- `./CLAUDE.md` 시작·끝 마커 쌍이 *정확히 1개*. 0·2쌍 이상이면 응답 경고 1줄.
- `CLAUDE.project.md`가 `Read`로 읽히는지.
- `.kd-backup-*` 백업 생성됐다면 그 경로 응답 1줄.

### 6. "이미 시작됨" — 마이그레이션 분기

`CLAUDE.project.md`가 이미 있다면 *막지 않고* 슬롯 manifest 기반 idempotent 마이그레이션. 슬롯 상태 4-way 분류·마커만 삽입·빈 골격 추가·결과 응답 4 패턴·안전 장치는 [references/프로젝트시작-마이그레이션.md](./references/프로젝트시작-마이그레이션.md).

핵심 원칙:
- *자급식 manifest* — 외부 `templates/` 의존 X. 디자이너 환경에서 그 경로 resolve 실패하므로 manifest 표가 단일 진실.
- *사용자 본문 보존 1순위* — 마커 한 줄 삽입과 *진짜 빠진 슬롯*만 추가. 사용자 데이터 *수정 X*.
- *손상 의심 즉시 중단* — 백업 + 슬롯 ID 명시 보고.

### 7. 다음 흐름 안내 (자연어 권유)

응답 본문 *맨 위* 항상:
> 이 폴더의 `CLAUDE.md`에 한 줄 추가했어요(`@CLAUDE.project.md`) — 새 대화창에서도 디자인 약속이 자동으로 이어지게요.

DESIGN.md 함께 박았다면:
> DESIGN.md를 발견해서 함께 import 했어요 — 토큰·컴포넌트 규약의 단일 진실로 쓸게요.

§3.2 백업 발생 시:
> 원래 `CLAUDE.md`는 `./CLAUDE.md.kd-backup-YYYYMMDD-HHmm`에 보관해뒀어요.

전역 마커 부재 시:
> 전역 디자이너 모드는 아직 안 켜져 있어요 — `/kdesigner:맨처음설정`으로 켜두시면 모든 폴더에서 자동 작동해요 (선택).

§1 진단 결과로 분기:

| 디렉토리 상태 | 진행 결 |
|---|---|
| 빈 디렉토리 | 의도 확인 질문 (§5.1) — [references/프로젝트시작-import-라인.md](./references/프로젝트시작-import-라인.md) §5.1 |
| `package.json`/`components/` | 기존 프로젝트 가져오기 결로 안내 → 사용자 동의 시 `import-existing` |

## 안전 장치

- **백업 우선** — 기존 `./CLAUDE.md` 있으면 *반드시* 백업 후 마커 격리 append. 백업 실패 시 추가 X.
- **마커로 격리** — `/kdesigner:디자인끄기`가 정확히 그 부분만 제거할 수 있게.
- **재실행 안전** — 이미 있으면 §6 분기 (idempotent).
- **비파괴** — 사용자 파일 *지우지 않음*. 추가·백업만.
- **외부 도구 호출 금지** — `npm`/네트워크 X. 이 명령은 *프로젝트 컨텍스트 박기*만. 실제 셋업은 `new-service`/`import-existing`.
- **전역 작업 금지** — `~/.claude/CLAUDE.md`는 *이 슬래시 책임 X*. `/kdesigner:맨처음설정` 담당.
