> 2. **파일이 존재하면** — 다른 어떤 응답도 만들기 전에 §6 마이그레이션 분기를 처음부터 끝까지 따라간다. 절대 만들지 않는 응답: "이미 시작되어 있어요 — `/kdesigner:디자인끄기`로 정리한 뒤 다시 부르세요" 같은 *분기 차단* 응답. 막지 말고 §6.4 패턴 중 하나로 *처리 결과*를 말한다.

# 프로젝트시작

## 언제 쓰나
이 작업 폴더에서 *디자인 작업을 시작*할 때. 빈 디렉토리든 기존 코드 폴더든 한 번에 — *이 프로젝트의 사실*(서비스명·디자인 토큰·컴포넌트 인덱스·스택·DESIGN.md 통합)을 박아 새 대화창에서도 컨텍스트가 이어진다.

## 동작

### 1. 디렉토리 진단 (읽기만)

`Read`/`Bash test`/`Glob`로 빠르게 확인하고 분기 결정에만 쓴다(중간 응답에는 노출 X):

| 항목 | 확인 | 분기 영향 |
|---|---|---|
| `./CLAUDE.project.md` 존재 | `Read` | 있으면 §6 마이그레이션 |
| `./CLAUDE.project.md.kd-archived-*` (하나 이상) + 본 파일 부재 | `Glob` | §3.1 archived 복원 분기 |
| `./DESIGN.md` 존재 | `Glob` | §2 DESIGN.md 통합 분기 |
| `~/.claude/CLAUDE.md` 마커(`<!-- kd:designer-mode:start -->`) | `Read` | 전역 켜짐 여부 (응답 톤에만 영향) |
| `package.json` 또는 `components/` | `Glob` | §5에서 `import-existing` 권유 |
| 완전 빈 디렉토리(또는 `.git`만) | `Glob` | §5에서 `new-service` 권유 |

**전역 마커 부재** — 전역(`/kdesigner:맨처음설정`)을 아직 안 켰음. 흐름을 막지는 않음 — `CLAUDE.project.md` 끝의 *페르소나 요약*이 단독 동작을 지탱. 단, §7 응답 끝에 *전역을 켜두면 더 편해요 (`/맨처음설정`)* 한 줄 권유.

### 2. DESIGN.md 통합 분기 (신설)

`https://getdesign.md/` 표준의 `DESIGN.md`(디자인 시스템 명세 표준 파일)가 프로젝트 루트에 있으면 *1순위 디자인 시스템 소스*로 통합한다.

| 상태 | 처리 |
|---|---|
| `./DESIGN.md` 존재 | §3.2 `./CLAUDE.md` import 블록에 `@DESIGN.md` 한 줄 추가. `CLAUDE.project.md` §디자인 시스템 §철학 섹션에 `> DESIGN.md를 1순위 소스로 사용하고 있어요 — 토큰·컴포넌트 규약은 그 파일이 단일 진실.` 한 줄 박기. |
| `./DESIGN.md` 부재 | 묻지 않음. 빈/기존 분기에서 `new-service` 또는 `import-existing`이 *그 안에서* 적절히 묻거나 권유. |

DESIGN.md *갱신*은 플러그인 책임 X — 사용자가 직접 갱신. 외부 표준이라 우리가 관리할 영역 아님.

### 3. 프로젝트 단위 활성화

#### 3.1 archived 발견 시 복원 분기

`./CLAUDE.project.md`은 *없는데* `./CLAUDE.project.md.kd-archived-*`가 하나 이상 있으면 — `/kdesigner:디자인끄기`로 끄고 다시 켜는 흐름.

`AskUserQuestion`:

> 이 폴더에 *이전에 디자이너 모드로 작업한 흔적*이 있어요(`CLAUDE.project.md.kd-archived-...`). 그때 정리해뒀던 디자인 약속·컴포넌트 정리를 *이어서* 쓸 수 있어요.
>
> - **이어서 쓰기** (이전 작업 내용 그대로 살리기, 다시 분석 필요 X)
> - **새로 시작** (이전 흔적은 보관해둔 채 비어있는 상태로 새로 시작)
> - **잘 모르겠어요** → 기본값: 이어서 쓰기

선택 결과대로:
- **이어서 쓰기**:
  - `ls -t ./CLAUDE.project.md.kd-archived-* | head -1` 로 가장 최근 archive 추출
  - `mv` 로 그 파일을 `./CLAUDE.project.md`로 복원 (cp 아님 — 한 archive를 두 자리에 두지 않음)
  - §3.2 import 라인 처리는 *복원된 파일 기준으로 그대로* 진행 (마커 검증 통과)
  - §3.3 템플릿 생성은 *스킵* (이미 `CLAUDE.project.md` 존재)
- **새로 시작**:
  - archive 파일은 *손대지 않음* (보관)
  - §3.3부터 그대로 진행 (템플릿으로 새 `CLAUDE.project.md` 생성)

응답에 복원 시 한 줄 노출:
> 이전 작업 그대로 이어서 시작해요 — `CLAUDE.project.md.kd-archived-YYYYMMDD-HHmm`을 다시 살렸어요.

#### 3.2 `./CLAUDE.md`에 import 라인 추가 (자동 로드 보장)

`CLAUDE.project.md`(그리고 있다면 `DESIGN.md`)는 *비표준 이름*이라 새 대화 시작 시 자동 로드되지 않는다 — 자동 로드되는 파일은 `./CLAUDE.md`, `./.claude/CLAUDE.md`, `./CLAUDE.local.md`, `~/.claude/CLAUDE.md`. 따라서 자동 로드되는 `./CLAUDE.md`에 공식 `@<path>` import 문법으로 박아 *새 대화에서도 디자인 약속이 그대로 이어지게* 한다.

마커 블록 내용 (§2 DESIGN.md 분기 결과 반영):

| DESIGN.md 존재? | 마커 블록 내용 |
|---|---|
| 있음 | `@DESIGN.md\n@CLAUDE.project.md` (2줄) |
| 없음 | `@CLAUDE.project.md` (1줄) |

처리 절차:

1. **`./CLAUDE.md` 존재 여부 확인** — `Read` 또는 `test -f ./CLAUDE.md`.

2-a. **없으면** (새로 생성):
   - `touch ./.kd-no-prior-claude-md` — 빈 마커 파일. `/kdesigner:디자인끄기`가 *우리 플러그인이 새로 만든 파일인지* 판단해서 통째 제거할 수 있게.
   - `Write ./CLAUDE.md`로 다음 내용만 박는다 (DESIGN.md 있으면 import 2줄, 없으면 1줄):
     ```
     <!-- kd:designer-mode:start -->
     @DESIGN.md
     @CLAUDE.project.md
     <!-- kd:designer-mode:end -->
     ```

2-b. **있으면** (기존 파일에 마커 격리해 추가):
   - **백업** — `cp ./CLAUDE.md ./CLAUDE.md.kd-backup-<YYYYMMDD-HHmm>` (timestamp는 `date +%Y%m%d-%H%M`). `/kdesigner:디자인끄기`에서 *원본 그대로* 복원할 수 있게.
   - **append** — 기존 파일 끝에 빈 줄 하나 + 마커 격리 블록 append (DESIGN.md 분기 반영).

3. **마커 검증** — append/생성 후 `Read ./CLAUDE.md`로 다시 읽어 시작 마커와 끝 마커가 *정확히 1쌍*인지 확인. 0쌍 또는 2쌍 이상이면 응답 끝에 경고 1줄 노출 ("`./CLAUDE.md`에 디자이너 마커가 정상이 아닌 상태예요 — 한 번 확인해주세요").

마커 사이는 *오직 `@DESIGN.md`(있을 때)와 `@CLAUDE.project.md` 줄만*. 디자인 시스템·페르소나 본문은 박지 않는다 — 본문은 그 파일들에 있고 `@import`이 자동 로드시킨다.

#### 3.3 `CLAUDE.project.md` 생성

§3.1에서 *이어서 쓰기*로 복원했으면 이 단계는 스킵.

`plugin/templates/CLAUDE.project.md`(이 플러그인의 템플릿) 내용을 그대로 가져와 현재 디렉토리 루트에 `CLAUDE.project.md`로 생성:

- `Read` 템플릿 → `Write` 프로젝트 루트에 (`./CLAUDE.project.md`)
- `{{서비스명}}`은 폴더 이름(`basename "$PWD"`)으로 채움
- 나머지 `{{...}}` placeholder는 *그대로 둔다* — `new-service`/`import-existing`이 이후 채울 영역
- §2 DESIGN.md 존재 분기였다면 §철학 슬롯 안내 인용구 끝에 `> DESIGN.md를 1순위 소스로 사용 중 — 토큰·컴포넌트 규약은 그 파일이 단일 진실.` 한 줄 추가 (사용자 답변이 들어가는 placeholder 본문은 손대지 않음)

### 4. 사이클 시작 시점 기록 (export-handoff용)

`export-handoff`가 *이번 사이클에 추가/변경된 파일만* 인계 README에 정리할 때 기준점으로 쓸 SHA를 박아둔다.

처리 절차:

1. **git 저장소가 아니면 스킵** (`git rev-parse --git-dir 2>/dev/null` 실패).
2. **commit 0개면 스킵** (`git rev-parse HEAD 2>/dev/null` 실패).
3. 그 외:
   - `mkdir -p ./.claude`
   - **이미 `.claude/.kd-session-base` 존재 시 덮어쓰지 X** (다른 흐름이 먼저 박았을 수 있음 — 처음 박는 1회만 책임).
   - 부재 시: `echo "$(git rev-parse HEAD)" > ./.claude/.kd-session-base`
4. **`.gitignore` 처리** (자동 추가):
   - `.gitignore`에 `.claude/.kd-session-base` 한 줄이 없으면 *append* (기존 줄 보존).
   - `.gitignore` 자체가 없으면 새로 만들어 그 한 줄만 박기.
   - `.claude/` 디렉토리 자체는 gitignore X.

### 5. 검증

- 프로젝트 루트 `./CLAUDE.md`에 시작·끝 마커 쌍이 *정확히 1개*인지 `Read`로 확인. 0쌍·2쌍 이상이면 응답에 경고 1줄.
- `CLAUDE.project.md`가 `Read`로 읽히는지 확인.
- `./CLAUDE.md.kd-backup-*` 백업 파일이 생성됐다면 그 경로 기억(응답에 1줄 노출).

### 6. "이미 시작됨" — 마이그레이션 분기 (idempotent, 자급식)

**[필수 행동 — 분기 진입 시 절대 생략 금지]**

`CLAUDE.project.md`가 이미 있다면 흐름을 *막지 않는다*. 아래 §6.0 → §6.1 → §6.2 → §6.4를 *순서대로 반드시 실행*한다. "이미 시작됨"이라는 일반 응답을 만드는 것 금지 — 응답은 §6.4 패턴 중 하나여야 한다.

#### 6.1 슬롯 상태 분류

1. **반드시** `Read ./CLAUDE.project.md` (사용자 파일).
2. §6.0 manifest의 각 슬롯에 대해 다음 4-way 분류:

| 상태 | 판정 조건 | 처리 |
|---|---|---|
| **정상** | 마커 ID `<!-- kd:slot:ID -->` + 한국어 헤더 둘 다 있음 | 건드리지 X |
| **마커만 부재** | 마커 ID 없는데 한국어 헤더가 있음 | §6.2-A 마커만 삽입 |
| **둘 다 부재** | 마커 ID 없고 한국어 헤더도 없음 | §6.2-B 빈 골격 추가 |
| **손상 의심** | 같은 마커 ID 2회+ / 같은 헤더 2회+ (마커 0개) | §6.5 즉시 중단 + 보고 |

분류 결과:
- 처리 대상 0개 (모두 정상) → §6.4 "이미 최신" 응답
- 처리 대상 1개 이상 → §6.2로 진행

DESIGN.md 분기 처리: §2에서 `./DESIGN.md` 발견 + `./CLAUDE.md` import 블록에 `@DESIGN.md` 없으면 §3.2 처리로 *그 한 줄 추가*. 이미 있으면 스킵.

#### 6.2-A 마커만 삽입

"마커만 부재" 분류된 슬롯들에 대해:

1. **백업 우선** — `cp ./CLAUDE.project.md ./CLAUDE.project.md.kd-migrate-<YYYYMMDD-HHmm>`.
2. **마커 한 줄 삽입** — 사용자 파일에서 해당 한국어 헤더의 *정확 일치* 라인을 찾아, 그 라인 *바로 위*에 `<!-- kd:slot:ID -->\n` 한 줄 삽입.
3. **본문은 절대 손대지 X** — 사용자가 채운 모든 내용 보존.
4. *답을 묻지 않음* — 묵묵히 모든 "마커만 부재" 슬롯 처리 후 §6.2-B로.

#### 6.2-B 빈 골격 추가

"둘 다 부재" 분류된 슬롯들을 §6.0 manifest의 *해당 슬롯 빈 골격*을 마커 + 헤더 + placeholder 본문 형태로 append:
```

<!-- kd:slot:ID -->
## 한국어 헤더 (or ### 으로 manifest 명시 그대로)
> 안내 인용구 (manifest의 빈 골격 본문 그대로)

- {{placeholder 1}}
- {{placeholder 2}}
```

삽입 위치 결정:
1. manifest 순서상 *그 슬롯 직전 슬롯*이 사용자 파일에 있으면 → 그 슬롯 끝 직후에 삽입.
2. 직전 슬롯이 없으면 → *직후 슬롯* 직전에 삽입.
3. 둘 다 없으면 → 사용자 파일 끝에 append.

placeholder(`{{...}}`)는 그대로 — 디자이너가 자연어로 발화할 때 다른 Skill(`aesthetic-guard`/`design-system-guard` 등)이 채움.

#### 6.4 결과 응답 패턴 (필수 — 일반 "이미 시작됨" 응답 금지)

§6.1 분류 결과에 따라 *반드시* 아래 패턴 중 하나로 응답.

**Case 1 — 처리 대상 0개 (모두 정상)**:

> 이 프로젝트는 *이미 최신 상태*예요. 추가하거나 정리할 게 없어요.

**Case 2 — §6.2-A만 발생**:

> 이 프로젝트의 *내부 표시*를 최신으로 정리했어요. 화면에는 변화가 없고, 다음 업데이트가 더 깔끔하게 동작하도록 표시만 추가한 거예요. 이미 채워두신 내용은 그대로 보존했어요.

**Case 3 — §6.2-B만 발생**:

> 이 프로젝트를 *최신으로* 업데이트했어요. 이번에 추가된 자리:
> - {{슬롯 한국어 이름}}
> - ...
>
> 이미 채워두신 내용은 그대로 보존했어요. 비어있는 새 자리는 *지금 채우지 X* — 첫 화면 만들 때 *어떤 분위기로?* 같은 *질문 1개*로 자연스레 채워져요.

**Case 4 — §6.2-A + §6.2-B 모두 발생**:

> 이 프로젝트를 *최신으로* 업데이트했어요. 이번에 추가된 자리:
> - {{슬롯 한국어 이름}}
> - ...
>
> 그리고 기존 슬롯 몇 개의 *내부 표시*도 함께 정리했어요. 이미 채워두신 내용은 그대로 보존했어요. 비어있는 새 자리는 첫 화면 흐름에서 자연스레 채워져요.

#### 6.5 안전 장치

- **백업 우선** — 마이그레이션 *전*에 `./CLAUDE.project.md`를 `.kd-migrate-<YYYYMMDD-HHmm>` 접미사로 백업. 백업 실패 시 마이그레이션 자체를 *중단* + 사용자에게 보고.
- **3-way 분류 후 손상 의심 시 즉시 중단** — §6.1 표의 "손상 의심" 행 한 건이라도 발견되면 *모든 자동 추가 중단* + 사용자에게 슬롯 ID 명시해 보고.
- **마이그레이션 후 검증** — `Read`로 다시 읽어 *모든 슬롯 ID가 정확히 1번씩* 존재하는지 확인. 0번 또는 2번 이상이면 백업 경로 안내 + 수동 정리 권유.
- **사용자 본문 보존 1순위** — §6.2-A는 마커 한 줄만 삽입, §6.2-B는 *진짜 빠진 슬롯*에만 동작. 사용자 데이터를 *수정하지 않음*.

#### 6.6 §3~§5와의 관계

§6 마이그레이션 분기는 *이미 시작됨* 상태에서만 들어가므로:
- §2 DESIGN.md 분기 — 그대로 적용 (사이드이펙트 없음, 추가만)
- §3 (프로젝트 단위 활성화) — 스킵 (이미 활성화돼 있음)
- §5 (검증) — 그대로 적용 (마커 검증)
- §4 (사이클 시작 SHA) — 이미 박혀 있으면 그대로, 없으면 박기
- §7 (다음 흐름 안내) — 마이그레이션 후 디자이너의 *원래 의도*는 모르므로, §6.4 응답 끝의 다음 행동 1개로 *자연어 권유* — "이제 어떤 화면을 더 만들어볼까요?" 또는 "지금까지 작업을 보여드릴까요?"

### 7. 다음 흐름 안내 (자연어 권유)

응답 본문 *맨 위*에 항상 다음 1줄을 노출(자연어 권유 분기 직전):

> 이 폴더의 `CLAUDE.md`에 한 줄 추가했어요(`@CLAUDE.project.md`) — 새 대화창에서도 디자인 약속이 자동으로 이어지게요.

§2 DESIGN.md 분기에서 `@DESIGN.md`도 함께 박았다면:

> DESIGN.md를 발견해서 함께 import 했어요 — 토큰·컴포넌트 규약의 단일 진실로 쓸게요.

§3.2에서 `./CLAUDE.md` 백업이 발생했다면(2-b 분기) 추가로 1줄:

> 원래 `CLAUDE.md`는 `./CLAUDE.md.kd-backup-YYYYMMDD-HHmm`에 보관해뒀어요.

전역(`~/.claude/CLAUDE.md`) 마커 부재였다면:

> 전역 디자이너 모드는 아직 안 켜져 있어요 — `/kdesigner:맨처음설정`으로 켜두시면 모든 폴더에서 자동 작동해요 (선택).

그다음 §1 진단 결과로 분기:

| 디렉토리 상태 | 권유 응답 |
|---|---|
| 빈 디렉토리(또는 `.git`만) | "**새 디자인 시작**해볼까요?" — 사용자가 응 → `new-service` Skill |
| `package.json`/`components/` 존재 | "**기존 프로젝트 가져오기** 흐름으로 정리해드릴까요?" — 응 → `import-existing` Skill |

추가 분기 — `CLAUDE.project.md` §source-repo 슬롯이 *채워져 있고* `마지막 sync 시점`이 *수일 이상 지났거나 비어있음*이면(`import-existing` A 분기 후 본 레포에 새 변경이 누적됐을 가능성) 권유 응답에 1줄 첨부:

> 원본 레포 갱신분 가져오려면 "**최신화해줘**" 한 마디면 돼요(`design-sync`).

슬래시로 직접 호출하지 않음 — 자연어로 발화하면 Skill이 자동 발동(PRD §6 "자연어 > 슬래시").

## 안전 장치

- **백업 우선** — 기존 `./CLAUDE.md`가 있으면 *반드시* 백업 (`cp`) 후 마커 격리 append. 백업 실패 시 추가 X.
- **마커로 격리** — 추가 내용을 `<!-- kd:designer-mode:start -->`~`end` 마커로 감싸 `/kdesigner:디자인끄기`가 정확히 그 부분만 제거할 수 있게.
- **재실행 안전** — `CLAUDE.project.md`/마커가 이미 있으면 덮지 않고 §6 분기 (idempotent).
- **비파괴** — 어떤 경우에도 사용자 파일을 *지우지* 않음. 추가·백업만.
- **외부 도구 호출 금지** — `npm`/네트워크 호출 X. 이 명령은 *프로젝트 컨텍스트 박기*만 담당. 실제 셋업(스택 초기화·컴포넌트 스캔)은 `new-service`/`import-existing` Skill이.
- **전역 작업 금지** — `~/.claude/CLAUDE.md`는 *이 슬래시의 책임 X*. `/kdesigner:맨처음설정`이 담당.
