# §5. 이미 켜져 있을 때 — 마이그레이션 분기 (idempotent, 자급식)

**[필수 행동 — 분기 진입 시 절대 생략 금지]**

전역에 `<!-- kd:designer-mode:start -->` 마커가 이미 있다면 흐름을 *막지 않는다*. 아래 §5.0 → §5.1 → §5.2 → §5.4를 *순서대로 반드시 실행*. "이미 켜져 있어요" 일반 응답 금지 — 응답은 §5.4 패턴 중 하나.

## §5.0 전역 슬롯 manifest (자급식 — 외부 파일 의존 X)

`templates/` 외부 Read 시도 X — 디자이너 환경에서 그 경로는 resolve 실패.

**전역(`~/.claude/CLAUDE.md`) 슬롯 manifest** — `<!-- kd:designer-mode:start -->`/`end` 사이만 대상:

| ID | 한국어 헤더 | 카테고리 | 빈 골격 본문 |
|---|---|---|---|
| `designer-profile` | `## 미학 학습 (자동 누적·디자이너 작성 불필요)` | 컨테이너 | 헤더 + 안내 인용구 (자식 슬롯 2개 별도 배치) |
| `avoidance` | `### 피하고 싶은 디자인 (자동 누적 슬롯)` | 자동 누적(빈 골격) | placeholder — `aesthetic-guard`·`feedback-curator`가 사후 누적 |
| `tone-extracted` | `### 평소 톤 (자동 추출 슬롯)` | 자동 추출(빈 골격) | placeholder 3줄 — `aesthetic-guard`가 작업 결과에서 자연스레 누적 |

> 라운드 2(2026-05-12)부터 *디자이너 프로필 인터뷰는 완전 제거*. 라운드 2 후속(2026-05-12)에 한 발 더 — *입력 요구 슬롯 자체를 제거*했다. `fav-references`(레퍼런스 URL)·`portfolio`(포트폴리오 URL)는 빈 골격조차 만들지 않는다. `aesthetic-guard`는 본문 *고정 클리셰 회피*(보라 그라디언트·이니셜 박스 아바타·균등 카드 그리드·Inter)를 기본값으로 동작하고, 자동 누적 슬롯 2개(`avoidance`·`tone-extracted`)만 작업 진행하며 채워간다.

## §5.1 슬롯 상태 분류

1. **반드시** `Read ~/.claude/CLAUDE.md`.
2. *마커 격리 블록* 안만 대상으로 §5.0 manifest 각 슬롯에 4-way 분류 (마커 밖 사용자 원본은 손대지 X):

| 상태 | 판정 조건 | 처리 |
|---|---|---|
| **정상** | 마커 ID + 한국어 헤더 둘 다 | 건드리지 X |
| **마커만 부재** | 헤더만 있음 | §5.2-A 마커만 삽입 |
| **둘 다 부재** | 마커·헤더 모두 X | §5.2-B 빈 골격 추가 |
| **손상 의심** | 같은 마커 ID 2회+ / 같은 헤더 2회+ (마커 0개) | §5.5 즉시 중단 + 보고 |

분류 결과:
- 처리 대상 0개 → §5.4 "이미 최신"
- 처리 대상 1개 이상 → §5.2

## §5.2-A 마커만 삽입

"마커만 부재" 슬롯들:

1. **백업 우선** — `cp ~/.claude/CLAUDE.md ~/.claude/CLAUDE.md.kd-migrate-<YYYYMMDD-HHmm>`.
2. **마커 한 줄 삽입** — 한국어 헤더 *정확 일치* 라인 *바로 위*에 `<!-- kd:slot:ID -->\n`.
3. **본문은 절대 손대지 X** — 사용자가 채운 모든 내용 보존.
4. *답을 묻지 않음* — 묵묵히 처리 후 §5.2-B로.

## §5.2-B 빈 골격 추가

**모든 카테고리: 묻지 않음**. §5.0 manifest의 *해당 슬롯 빈 골격*을 마커 + 헤더 + placeholder 본문 형태로 append:

```
<!-- kd:slot:ID -->
## 한국어 헤더
> 안내 인용구

- {{placeholder 1}}
- {{placeholder 2}}
```

삽입 위치:
1. manifest 순서상 *그 슬롯 직전 슬롯*이 있으면 → 그 슬롯 끝 직후.
2. 직전 슬롯이 없으면 → *직후 슬롯* 직전.
3. 둘 다 없으면 → 사용자 파일 끝(마커 직전)에 append.

placeholder는 그대로 — `aesthetic-guard`가 첫 작업 시 자연스레 1개씩 묻고 채움.

## §5.3 — 인터뷰 단계 제거됨

라운드 2부터 *인터뷰 단계 제거*. 빈 슬롯은 모두 *사후 누적*만 — `aesthetic-guard`가 첫 작업 시.

## §5.4 결과 응답 패턴

§5.1 분류 결과에 따라 *반드시* 아래 패턴 중 하나. 절대 만들지 않는 응답: "이미 켜져 있어요 — 다시 끄려면..." 같은 *분기 차단*.

**Case 1 — 처리 대상 0개**:
> 디자이너 모드 *이미 최신 상태*예요. 추가하거나 정리할 게 없어요.
>
> 프로젝트 단위 셋업은 `/프로젝트시작`으로 분리됐어요 — 작업 폴더에서 부르시면 됩니다.

**Case 2 — §5.2-A만**:
> 디자이너 모드의 *내부 표시*를 최신으로 정리했어요. 화면에는 변화가 없고, 다음 업데이트가 더 깔끔하게 동작하도록 표시만 추가한 거예요. 이미 채워두신 내용은 그대로 보존했어요.
>
> 프로젝트 단위 셋업은 `/프로젝트시작`으로 분리됐어요.

**Case 3 — §5.2-B만**:
> 디자이너 모드를 *최신으로* 업데이트했어요. 이번에 추가된 자리:
> - {{슬롯 한국어 이름}}
> - ...
>
> 이미 채워두신 내용은 그대로 보존했어요. 비어있는 새 자리는 *지금 채우지 X* — 첫 화면 만들 때 *어떤 분위기로?* 같은 질문 1개로 자연스레.
>
> 프로젝트 단위 셋업은 `/프로젝트시작`으로 분리됐어요.

**Case 4 — §5.2-A + §5.2-B**:
> 디자이너 모드를 *최신으로* 업데이트했어요. 이번에 추가된 자리:
> - {{슬롯 한국어 이름}}
> - ...
>
> 그리고 기존 슬롯 몇 개의 *내부 표시*도 함께 정리했어요. 이미 채워두신 내용은 그대로 보존했어요. 비어있는 새 자리는 첫 화면 흐름에서 자연스레 채워져요.
>
> 프로젝트 단위 셋업은 `/프로젝트시작`으로 분리됐어요.

각 슬롯의 한국어 이름(Case 3·4 응답):

| ID | 한국어 이름 |
|---|---|
| `designer-profile` | 미학 학습 (자동 누적) |
| `avoidance` | 피하고 싶은 디자인 (자동 누적) |
| `tone-extracted` | 평소 톤 (자동 추출) |

## §5.5 안전 장치

- **백업 우선** — 마이그레이션 *전*에 `.kd-migrate-<YYYYMMDD-HHmm>` 백업. 실패 시 *중단* + 보고.
- **손상 의심 즉시 중단** — §5.1 "손상 의심" 한 건이라도 → *자동 추가 중단* + 슬롯 ID 명시 보고.
- **마이그레이션 후 검증** — `Read`로 다시 읽어 *모든 슬롯 ID가 정확히 1번씩*. 0번·2번 이상이면 백업 경로 + 수동 정리 권유.
