# §6. 이미 시작됨 — 마이그레이션 분기 (idempotent, 자급식)

**[필수 행동 — 분기 진입 시 절대 생략 금지]**

`CLAUDE.project.md`가 이미 있다면 흐름을 *막지 않는다*. 아래 §6.0 → §6.1 → §6.2 → §6.4를 *순서대로 반드시 실행*. "이미 시작됨" 일반 응답 만드는 것 금지 — 응답은 §6.4 패턴 중 하나여야 한다.

## §6.0 슬롯 manifest (자급식 — 외부 파일 의존 X)

§6의 모든 처리는 *아래 manifest 표만 참조*. `templates/` 외부 Read 시도 X — 디자이너 환경에서 그 경로는 resolve 실패.

| ID | 한국어 헤더 | 카테고리 | 빈 골격 본문 |
|---|---|---|---|
| `design-philosophy` | `### 철학` | 빈 골격 | `{{이 디자인이 추구하는 톤·결을 1~3줄}}` |
| `project-tone` | `### 톤 한 단어` | 빈 골격 | `{{미니멀 / 브루탈 / 에디토리얼 / ...}}` |
| `project-references` | `### 레퍼런스` | 빈 골격 | placeholder 2줄 |
| `project-avoidance` | `### 피하고 싶은 디자인 (이 프로젝트 한정)` | 빈 골격 | placeholder 2줄 |
| `design-tokens` | `### 핵심 토큰` | 빈 골격 | 색·간격·둥글기·타이포 placeholder |
| `tech-stack` | `## 사용 스택` | 빈 골격 | 스택 placeholder |
| `source-repo` | `## 원본 레포 (자동 관리)` | 자동 관리(빈 골격) | 원본 URL / branch / 진단 시점 SHA / 마지막 sync — 모두 `{{없음}}` 시작 |
| `design-mode-config` | `## 디자인 모드 설정 (자동 관리)` | 자동 관리(빈 골격) | 토글 / mock 경로 / dev 스크립트 / 환경변수 — `{{없음}}` 시작 |
| `share-policy` | `## 공유 정책 (자동 관리)` | 자동 관리(빈 골격) | 회사 프로젝트 / 회사명 / 외부 도구 — `{{미답변}}` 시작 |
| `publishing-boundary` | `## 디자이너 작업 영역 경계 (개발자가 조정)` | 빈 골격 | 허용/금지/패턴 가드 3섹션. `import-existing` A 분기에서 시드, 비어있으면 hook이 Next.js 기준 기본값 |
| `components` | `## 사용 가능한 컴포넌트` | 빈 골격 | 컴포넌트 인덱스 placeholder |
| `pages` | `## 사용 가능한 페이지` | 빈 골격 | 페이지 인덱스 placeholder — `import-existing` §4.5에서 채움 |
| `share-history` | `## 공유 이력` | 자동 관리(빈 골격) | 일자/분류/대상/URL/상태 표 헤더만, 데이터 0개 |
| `last-work` | `## 마지막 작업` | 빈 골격 | 비워둠 |

각 슬롯의 *정확한* 빈 골격 본문은 디자이너 프로젝트 안 *최신 `./CLAUDE.project.md`*가 신규 설치자에게 깔린 모습 그대로 — placeholder(`{{...}}`)는 그대로.

## §6.1 슬롯 상태 분류

1. **반드시** `Read ./CLAUDE.project.md`.
2. §6.0 manifest 각 슬롯에 4-way 분류:

| 상태 | 판정 조건 | 처리 |
|---|---|---|
| **정상** | 마커 ID `<!-- kd:slot:ID -->` + 한국어 헤더 둘 다 있음 | 건드리지 X |
| **마커만 부재** | 마커 ID 없는데 한국어 헤더가 있음 | §6.2-A 마커만 삽입 |
| **둘 다 부재** | 마커 ID 없고 한국어 헤더도 없음 | §6.2-B 빈 골격 추가 |
| **손상 의심** | 같은 마커 ID 2회+ / 같은 헤더 2회+ (마커 0개) | §6.5 즉시 중단 + 보고 |

분류 결과:
- 처리 대상 0개 → §6.4 "이미 최신"
- 처리 대상 1개 이상 → §6.2

DESIGN.md 분기: §2에서 `./DESIGN.md` 발견 + `./CLAUDE.md` import 블록에 `@DESIGN.md` 없으면 §3.2 처리로 *그 한 줄 추가*. 이미 있으면 스킵.

## §6.2-A 마커만 삽입

"마커만 부재" 슬롯들:

1. **백업 우선** — `cp ./CLAUDE.project.md ./CLAUDE.project.md.kd-migrate-<YYYYMMDD-HHmm>`.
2. **마커 한 줄 삽입** — 해당 한국어 헤더 *정확 일치* 라인 *바로 위*에 `<!-- kd:slot:ID -->\n`.
3. **본문은 절대 손대지 X** — 사용자가 채운 모든 내용 보존.
4. *답을 묻지 않음* — 묵묵히 처리 후 §6.2-B로.

## §6.2-B 빈 골격 추가

"둘 다 부재" 슬롯들을 §6.0 manifest의 *해당 슬롯 빈 골격*을 마커 + 헤더 + placeholder 본문 형태로 append:

```
<!-- kd:slot:ID -->
## 한국어 헤더
> 안내 인용구 (manifest 빈 골격 그대로)

- {{placeholder 1}}
- {{placeholder 2}}
```

삽입 위치:
1. manifest 순서상 *그 슬롯 직전 슬롯*이 사용자 파일에 있으면 → 그 슬롯 끝 직후.
2. 직전 슬롯이 없으면 → *직후 슬롯* 직전.
3. 둘 다 없으면 → 사용자 파일 끝에 append.

placeholder는 그대로 — `aesthetic-guard`·`design-system-guard`가 자연어 발화 때 채움.

## §6.4 결과 응답 패턴 (필수 — 일반 "이미 시작됨" 응답 금지)

§6.1 분류 결과에 따라 *반드시* 아래 패턴 중 하나.

**Case 1 — 처리 대상 0개**:
> 이 프로젝트는 *이미 최신 상태*예요. 추가하거나 정리할 게 없어요.

**Case 2 — §6.2-A만 발생**:
> 이 프로젝트의 *내부 표시*를 최신으로 정리했어요. 화면에는 변화가 없고, 다음 업데이트가 더 깔끔하게 동작하도록 표시만 추가한 거예요. 이미 채워두신 내용은 그대로 보존했어요.

**Case 3 — §6.2-B만 발생**:
> 이 프로젝트를 *최신으로* 업데이트했어요. 이번에 추가된 자리:
> - {{슬롯 한국어 이름}}
> - ...
>
> 이미 채워두신 내용은 그대로 보존했어요. 비어있는 새 자리는 *지금 채우지 X* — 첫 화면 만들 때 *어떤 분위기로?* 같은 *질문 1개*로 자연스레.

**Case 4 — §6.2-A + §6.2-B 모두 발생**:
> 이 프로젝트를 *최신으로* 업데이트했어요. 이번에 추가된 자리:
> - {{슬롯 한국어 이름}}
> - ...
>
> 그리고 기존 슬롯 몇 개의 *내부 표시*도 함께 정리했어요. 이미 채워두신 내용은 그대로 보존했어요. 비어있는 새 자리는 첫 화면 흐름에서 자연스레 채워져요.

각 슬롯의 한국어 이름(Case 3·4 응답 본문에):

| ID | 한국어 이름 |
|---|---|
| `design-philosophy` | 디자인 철학 |
| `project-tone` | 톤 한 단어 |
| `project-references` | 프로젝트 레퍼런스 |
| `project-avoidance` | 프로젝트 한정 회피 |
| `design-tokens` | 핵심 토큰 |
| `tech-stack` | 사용 스택 |
| `source-repo` | 원본 레포 정보 |
| `design-mode-config` | 디자인 모드 설정 |
| `share-policy` | 공유 정책 |
| `publishing-boundary` | 디자이너 작업 영역 경계 |
| `components` | 사용 가능한 컴포넌트 |
| `pages` | 사용 가능한 페이지 |
| `share-history` | 공유 이력 |

## §6.5 안전 장치

- **백업 우선** — 마이그레이션 *전*에 `.kd-migrate-<YYYYMMDD-HHmm>` 접미사로. 백업 실패 시 마이그레이션 *중단* + 사용자 보고.
- **손상 의심 즉시 중단** — §6.1 표 "손상 의심" 한 건이라도 → *자동 추가 중단* + 슬롯 ID 명시 보고.
- **마이그레이션 후 검증** — `Read`로 다시 읽어 *모든 슬롯 ID가 정확히 1번씩* 존재. 0번·2번 이상이면 백업 경로 + 수동 정리 권유.
- **사용자 본문 보존 1순위** — §6.2-A는 마커 한 줄만, §6.2-B는 *진짜 빠진 슬롯*에만. 사용자 데이터 *수정 X*.

## §6.6 §3~§5와의 관계

§6은 *이미 시작됨* 상태에서만 진입:
- §2 DESIGN.md — 그대로 적용 (사이드이펙트 없음, 추가만)
- §3 활성화 — 스킵 (이미 활성화)
- §5 검증 — 그대로 적용 (마커 검증)
- §4 사이클 SHA — 박혀 있으면 그대로, 없으면 박기
- §7 다음 흐름 — 마이그레이션 후 디자이너 *원래 의도* 모름 → §6.4 응답 끝의 다음 행동 1개로 자연어 권유 ("이제 어떤 화면을 더 만들어볼까요?" / "지금까지 작업을 보여드릴까요?")
