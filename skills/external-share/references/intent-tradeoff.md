# §1·§2. 의도 분류 + Trade-off 안내

## §1. 의도 분류 (AskUserQuestion 1회)

"왜 묻는지" 1줄 + "잘 모르겠어요" 옵션.

> 어떤 식으로 공유하실 건가요? *왜 묻냐면, 누구에게·얼마나 보여줄지에 따라 안전하게 풀어내는 방식이 다르거든요.*
>
> - **잠깐만 보여줄 거예요** (5분~1시간, 통화하면서 같이 보기) — 내 컴퓨터 켜진 동안만 통하는 임시 통로
> - **며칠 동안 시안 돌릴 거예요** (팀·동료 리뷰 받기) — 외부에 정식으로 올림, 무료 플랜 가능
> - **계속 볼 수 있게 하고 싶어요** (클라이언트가 며칠~몇 주 봄) — 외부 정식 + 비밀번호 권장
> - **진짜 외부 공개해요** (인터넷 누구나 보게) — 보안 점검 강화 후 정식 공개
> - **잘 모르겠어요** → 기본값: 두 번째 (며칠 시안 돌리기)

선택을 `INTENT = A | B | C | D` 로 보관.

## §2. Trade-off 안내 (선택 직후 본문)

선택지 *밖의* 옵션도 가볍게 — 디자이너가 결정 검증할 수 있게:

```
A. 잠깐만 보여주기 (임시 통로)
   ✓ 1분 셋업, 회원가입 X
   ✗ 내 컴터 끄면 사라짐, URL이 매번 바뀔 수 있음
   ⚠ 인터넷에서 내 컴터로 통로 뚫는 방식 — 회사 보안 정책 있다면 IT팀 확인

B. 며칠 시안 돌리기 (무료 정식 배포)
   ✓ 항상 접근 가능, URL 안 바뀜
   ✗ 외부 서비스 회원가입 필요 (이메일+비번)
   ⚠ 무료 플랜은 *공개*가 기본 — 검색엔진엔 안 잡혀도 URL 알면 누구나 봄

C. 비밀번호 걸어 공유 (지속)
   ✓ B와 같지만 지정한 사람만 봄
   ✗ 일부 도구는 유료 플랜이 필요할 수 있음

D. 진짜 외부 공개
   ⚠ 회사 프로젝트면 *반드시* 사전 점검:
     - 더미 데이터만 들어있나?
     - 회사 로고/내부 정보 노출 안 되나?
     - 도메인 정책은 IT팀과 합의됐나?
```

선택을 바꾸고 싶으면 다시 물어볼 수 있다고 한 줄.

## §5. 회사 프로젝트 가드 (1회 질문 + 캐시)

`CLAUDE.project.md` §공유 정책 슬롯(`<!-- kd:slot:share-policy -->`)에서 *회사 프로젝트 여부* 미답변이면:

> 이 프로젝트가 *회사 일이거나 클라이언트 프로젝트*인가요? *왜 묻냐면, 그렇다면 외부 공유 방식·도구 선택이 달라지거든요(비밀번호·보안 점검 강화).*
>
> - 예 (회사·클라이언트)
> - 아니오 (개인 학습·사이드)
> - 잘 모르겠어요 → 보수적으로 *예*

답을 §공유 정책에 캐시 (`Edit`). 다음 호출부터 묻지 않음.

*예*면 회사명 키워드 1~3개 추가 묻기 (민감정보 스캔에 쓰임). "잘 모르겠어요"는 *없음*.

분기:
- *예* → §1에서 A/B 선택했다면 *경고* 1줄 ("회사 프로젝트면 C(비밀번호)·D(점검 강화) 권장. 그래도 진행할까요?"). 동의 시 진행.
- *아니오* → 그대로 진행

## §6. 외부 의존성 동의 (첫 사용 시 1회)

§7에서 추천한 도구가 *처음 사용*이면 (CLI 인증 안 됨), 명시 동의:

> 이 도구는 *외부 서비스(<도구명>)에 코드를 올립니다*. 회원가입 한 번 + 로그인 흐름이 진행돼요. 진행할까요?
>
> - 진행
> - 다른 도구로 바꾸기
> - 취소

회원가입·로그인은 도구가 자체 안내(브라우저). `error-translator`가 인증 실패 시 가로채기.

캐시: §공유 정책에 *외부 도구 동의: 도구명 (날짜)* 한 줄.
